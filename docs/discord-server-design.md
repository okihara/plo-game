# BabyPLO Discord サーバー設計

2026-08-17 の打ち合わせ（[meeting-2026-08-17.md](meeting-2026-08-17.md)）で決まった「Discord サーバー作成（9月目処）」の設計書。
Discord 側の構成（チャンネル・ロール・ルール）、セットアップ手順、コピペ用テンプレ文をまとめる。

- 本書のスコープは **Discord サーバーそのもの**。アプリからの自動通知・アプリ内の招待リンク導線・Discord ログインは対象外（末尾「将来の拡張」に整理）
- コーチング系（コーチロール・監修付きハンド議論・有料チャンネル）は **初期構成に含めない**。需要が見えてから別途設計する

---

## 1. 目的と運営方針

### 用途（3本柱）

| 用途 | 内容 | 主なチャンネル |
| --- | --- | --- |
| 不具合報告 | ユーザーがシステム問題を報告し、運営が状況を返す | `#バグ報告` |
| プレイ募集 | 毎日 22:00 のデイリートナメへの集合、リング戦の呼びかけ | `#今夜のトナメ` `#プレイ募集` |
| ハンド議論 | プレイしたハンドを持ち寄って話す。PLO のレベルアップと普及の場 | `#ハンド議論` |

### 方針

- **叩かれない場所にする**。ポーカー界隈の「言うと叩かれるから言いたくない」空気を持ち込まない。ハンド議論は批判ではなく質問から始める（ルール第2条）
- **X と Discord の役割分担**。公式 X（[@babyplo4](https://x.com/babyplo4)）は告知の一次発信、Discord は双方向の場。X に流した告知・結果・アップデートは Discord にも転載する（逆は必須ではない）
- **日本語運用**。チャンネル名・ルール文は日本語。英語話者が来た場合は個別対応
- **最小体制で始める**。オーナー 1 名 + モデレーター 1〜2 名。チャンネル数も最初は絞り、要望が出てから増やす

## 2. サーバー基本設定

| 項目 | 設定値 | 理由 |
| --- | --- | --- |
| サーバー名 | `BabyPLO` | アプリ名と同一。検索・招待画面での認知一致 |
| アイコン | アプリの OGP 画像（`public/images/ogp.png` を正方形に切り出し） | ブランド統一 |
| コミュニティ機能 | **有効** | ルールスクリーニング・オンボーディング・フォーラム/アナウンスチャンネルを使うために必須 |
| 認証レベル | 中（登録から 5 分以上経過したアカウント） | 荒らし対策とハードルのバランス |
| 明示的コンテンツフィルタ | 全メンバーのメッセージをスキャン | 公開サーバーの標準 |
| DM 保護（AutoMod） | スパムメッセージ・メンション連打・不審リンクをブロック | RMT/宣伝スパム対策 |
| 既定の通知設定 | @mention のみ | 全メッセージ通知は離脱要因 |
| 既定のロール（@everyone） | 閲覧のみ、投稿不可 | ルール同意で `メンバー` が付くまで投稿させない |
| ルールチャンネル | `#ルール` | コミュニティ機能の必須項目 |
| モデレーター専用チャンネル | `#mod-log` | 同上（監査ログ通知先） |
| 言語 | 日本語 | 表示・Discovery 用 |

### オンボーディング

コミュニティ機能の「オンボーディング」で次の流れを作る。

1. 参加 → ルールスクリーニング（`#ルール` の要約 7 条に同意）
2. 同意で `メンバー` ロール自動付与（投稿解禁）
3. 「まずやること」に `#自己紹介` `#今夜のトナメ` `#バグ報告` を提示
4. 既定チャンネル（初回に見える）は `#お知らせ` `#雑談` `#今夜のトナメ` の 3 つ

## 3. ロールと権限

### ロール一覧

| ロール | 対象 | 表示色 | 付与方法 |
| --- | --- | --- | --- |
| `運営` | サーバーオーナー・開発者 | 赤系 | 手動 |
| `モデレーター` | 運営が依頼した信頼できる常連 | 青系 | 手動 |
| `メンバー` | ルール同意済みの一般参加者 | なし | ルールスクリーニング同意で自動 |
| `Bot` | 将来の通知 Bot 用 | グレー | Bot 追加時に自動（今は作成のみ） |

`コーチ` ロールは今回作らない。コーチング系を導入するときに `メンバー` と `モデレーター` の間へ追加する。

### 権限マトリクス

| 権限 | @everyone | メンバー | モデレーター | 運営 |
| --- | :-: | :-: | :-: | :-: |
| チャンネル閲覧 | ○（公開のみ） | ○ | ○ | ○ |
| メッセージ送信 | × | ○ | ○ | ○ |
| ファイル添付・埋め込みリンク | × | ○ | ○ | ○ |
| スレッド作成・フォーラム投稿 | × | ○ | ○ | ○ |
| リアクション | × | ○ | ○ | ○ |
| @everyone / @here メンション | × | × | ○ | ○ |
| ボイス参加 | × | ○ | ○ | ○ |
| メッセージ管理（削除・ピン留め） | × | × | ○ | ○ |
| スレッド管理（閉じる・名前変更） | × | × | ○ | ○ |
| タイムアウト・キック | × | × | ○ | ○ |
| BAN | × | × | × | ○ |
| チャンネル・ロール・サーバー設定の管理 | × | × | × | ○ |
| `#お知らせ` `#アップデート情報` への投稿 | × | × | × | ○ |
| `#運営` `#mod-log` の閲覧 | × | × | ○ | ○ |

- `運営` には「管理者」権限を付ける（オーナー含め 2〜3 名まで）
- `モデレーター` に「管理者」は付けない。上表の個別権限のみ

| 水 | PLO8（Hi-Lo） | |

| チャンネル | 種類 | 投稿 | 目的 |
| --- | --- | --- | --- |
| `#運営` | テキスト | モデレーター | 運営相談。荒らし対応・イベント準備 |

### ハンドの共有方法（`#ハンド議論` `#バグ報告` 共通）

1. アプリのハンド履歴（`https://baby-plo.app/history`）で該当ハンドを開く
2. 共有メニューから次のいずれかを貼る
   - **リンクをコピー**: `https://baby-plo.app/hand/<id>` 形式の URL。Discord 上でプレビューが出るので基本はこれ
   - **画像をコピー**: ハンド画像を添付したいとき
   - **PokerStars形式でコピー**: テキストでアクションを追いたいとき（相手名は伏せて出力できる）
3. リンクだけだと流れが追いにくいので、`#ハンド議論` では自分の考えを本文に書き添える（5-4 参照）

## 5. コピペ用テンプレ文

### 5-1. `#ルール` 本文

```
📜 BabyPLO Discord ルール

1. 敬意を持って
   誰に対しても丁寧に。煽り・人格攻撃・差別的な発言は禁止です。

2. ハンド議論は「質問」から
   他人のプレイを笑わない、決めつけない。「なぜそうしたの？」「自分ならこうする、理由は…」の形で話しましょう。
   ここは間違えても叩かれない場所です。

3. 他人の情報を勝手に出さない
   本名・SNS・成績などの晒し行為、他サーバーや配信でのやり取りの無断転載は禁止です。

4. 宣伝・勧誘・RMT は禁止
   他サービスの宣伝、コーチングやサロンの勧誘、チップや通貨の売買、それに類する行為は禁止です。
   運営が許可した告知のみ例外です。

5. 不具合は #バグ報告 へ
   雑談に流すと運営が見落とします。テンプレに沿って 1 事象 1 投稿でお願いします。

6. チャンネルの用途を守る
   迷ったら #雑談 へ。運営・モデレーターが移動をお願いすることがあります。

7. 運営の判断が最終です
   ルールに書いていないことでも、場を悪くする行為には運営・モデレーターが対応します。
   タイムアウト → キック → BAN の順で判断します。

困ったこと・相談は運営に DM か #質問・初心者 へどうぞ。
```

### 5-4. `#ハンド議論` 投稿ガイドライン（フォーラムの投稿ガイドライン欄に設定）

```
1 投稿 = 1 ハンドでお願いします。

【書いてほしいこと】
・種目（PLO / PLO8 / 5-Card / Bomb Pot）とブラインド、トナメならレベル・残り人数
・自分のハンドとポジション、相手の人数

・結果（勝った負けた）は最初は伏せても OK。議論が偏らないので
・返信する人は「なぜそうしたの？」から。プレイを笑わない、決めつけない
・話が終わったら投稿者が「解決済み」タグを付けてください
```

## 6. セットアップ手順チェックリスト

Discord のデスクトップアプリまたはブラウザで、上から順に。所要時間は 1〜2 時間。

### サーバー作成と基本設定

- [ ] サーバーを作成（テンプレートは「オリジナルを作成」→「自分と友達のため」で空のサーバーにする）
- [ ] サーバー名 `BabyPLO`、アイコンをアップロード
- [ ] サーバー設定 → コミュニティを有効化（ルールチャンネル・モデレーターチャンネルを聞かれるので、この時点で `#ルール` と `#mod-log` を作らせる）
- [ ] サーバー設定 → 安全設定: 認証レベル「中」、明示的コンテンツフィルタ「全メンバー」
- [ ] サーバー設定 → AutoMod: スパム・メンション連打・不審リンクのブロックを有効化
- [ ] サーバー設定 → 概要: 既定の通知を「@mention のみ」、言語を日本語

### ロール

- [ ] `運営`（管理者 ON、色: 赤系、ロール別表示 ON）
- [ ] `モデレーター`（管理者 OFF。メッセージ管理・スレッド管理・メンバーのタイムアウト・キック・@everyone メンション ON、色: 青系、ロール別表示 ON）
- [ ] `メンバー`（既定の権限に加えてメッセージ送信・添付・スレッド作成・リアクション・ボイス接続 ON）
- [ ] `Bot`（権限なし。後で通知 Bot を入れるときのため）
- [ ] `@everyone` からメッセージ送信・スレッド作成・リアクション・ボイス接続を OFF（閲覧のみ）
- [ ] 自分に `運営` を付与

### カテゴリとチャンネル

- [ ] カテゴリ `📌 はじめに` を作り、`#ルール`（既存を移動）`#お知らせ`（アナウンス）`#アップデート情報`（アナウンス）`#自己紹介` を作成
- [ ] カテゴリ `🃏 BabyPLO` に `#雑談` `#今夜のトナメ` `#プレイ募集` `#ハンド議論`（フォーラム）`#質問・初心者` を作成
- [ ] カテゴリ `🛠 フィードバック` に `#バグ報告`（フォーラム）`#要望・アイデア` を作成
- [ ] カテゴリ `🔊 ボイス` に `トナメ実況` `雑談ボイス` を作成
- [ ] カテゴリ `🔒 運営` に `#運営` `#mod-log`（既存を移動）を作成し、カテゴリを `運営` `モデレーター` のみ閲覧に設定
- [ ] `#ルール` `#お知らせ` `#アップデート情報` を `運営` のみ送信可に設定（他ロールは閲覧・リアクションのみ）

## 7. 招待リンクの公開

- 招待リンクは **1 本だけ**運用する（無期限・無制限）。複数あると流入元が追えなくなる。荒らしに使われたら無効化して発行し直す
- 掲載先:
  1. 公式 X（[@babyplo4](https://x.com/babyplo4)）の固定ポストとプロフィール欄
  2. 毎日のトナメ告知ツイートに、開設後しばらく（1〜2 週間）は 1 行添える。文面は `.claude/skills/tournament-announce/SKILL.md` の運用に合わせて調整
  3. 打ち合わせ参加者・常連への個別案内
- **アプリ内導線は別タスク**。ロビーの X フォローバナー（`src/pages/SimpleLobby.tsx`）の隣に Discord バナーを置き、リンクは環境変数（例: `VITE_DISCORD_INVITE_URL`）で設定する想定。招待リンクをコードに直書きしない

## 8. 将来の拡張（今回は対象外）

リポジトリには現在 Discord 連携が存在しない（OGP プレビュー用の `Discordbot` UA 判定と、削除済み Discord OAuth の古い記述のみ）。将来やるならの当たりだけ残す。

### アプリ → Discord 通知（Webhook）

- トナメ結果: `TournamentManager.createTournament()` が登録する `onTournamentComplete` コールバック（`persistTournamentResults` の隣）から Webhook 投稿する
- 告知・結果ツイートの転載: `server/src/modules/tweet/twitterClient.ts` と `server/scripts/post-tweet.ts` の対にならって `discordClient.ts` / `post-discord.ts` を作り、既存スキル（`/tournament-announce` `/tournament-tweet` `/update-tweet`）の投稿ステップで X と同時に Discord へも送る
- Webhook URL は `DISCORD_WEBHOOK_URL` として `server/src/config/env.ts` と `server/.env.example`、Railway の環境変数に置く。会話やコミットに貼らない
- 注意: トナメはサーバーメモリ上に持つため、開催前のデプロイで消える。サーバー内から出す通知はその脆さを引き継ぐ。スキル経由の投稿の方が安定

### Discord ログイン

- `findOrCreateUser` はプロバイダ非依存なので、`/auth/discord` と `/auth/discord/callback` を足すだけで基本は動く
- 障壁: `User.email` `User.username` の一意制約（Twitter 側はプレースホルダで埋めている）、`twitterAvatarUrl` など Twitter 名義のアバター列、アカウント連携テーブルがないこと（1 ユーザー = 1 プロバイダ）
- 古い記述の掃除: `server/README.md` の `/auth/discord` 行、`schema.prisma` の `provider` コメント
